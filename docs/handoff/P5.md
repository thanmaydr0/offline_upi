# P5 integration handoff

P5 implemented the owned modules and tested them using backend/scripts/runtime.ts, which injects RealChain before P2's current factory can throw.

## P2 changes needed outside P5 ownership

1. backend/src/chain/index.ts: select RealChain for CHAIN_MODE=chain. RealChain constructor takes (BackendEnv, BackendDatabase); adapt factory/context to pass the app DB. Keep one relayer instance per wallet key/process.
2. backend/src/app.ts and server.ts: initialize SettlementService, mount settleRoutes(context, service), mount settlementWalletRoutes(context) before the existing wallet routes, and start ReconciliationJob(context, service).start() with shutdown cleanup. Alternatively use scripts/runtime.ts as the reference composition. Standard npm run dev currently still uses the old factory and cannot start with CHAIN_MODE=chain; the running P5 backend uses scripts/server-chain.ts.
3. backend/package.json: add "dev:chain": "tsx scripts/dev-chain.ts", "seed:demo": "tsx scripts/seed-demo.ts", and optionally "start:chain": "tsx scripts/server-chain.ts". P5 did not edit this P2-owned manifest. The requested npm aliases therefore remain unregistered.
4. backend/src/routes/onramp.ts: funding uncertainties intentionally leave orders processing. Consider passing a stable order ID into an extended fundCollateral signature and reconciling funding by CollateralFunded receipts before supporting automatic onramp recovery; do not blindly repeat uncertain funding. Settlement restart recovery is implemented and tested.
5. Integrate the auxiliary schema declarations into your normal migrations if desired. P5 currently initializes its own tables idempotently when constructing the services.

## P1 future contract improvements

Per-item status events would make failure-code recovery exact under concurrent redemptions; the current ABI only emits OK Redeemed events. Current failure-code derivation is documented as best effort. Consider emitting a payment hash/deadline so double-spend evidence can be recovered even when a redemption transaction calls through a contract wrapper.
