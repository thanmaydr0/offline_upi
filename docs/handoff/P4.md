# P4 handoff

## Core implementation

`mobile/src/core/index.ts` exports the real `keyService`, `voucherWallet`, `ledgerService`, and `receivedStore`, plus `getSecurityStatus` and clock/config helpers. SQLCipher is enabled in the existing `mobile/app.json`; database initialization refuses to proceed unless the native driver reports a cipher version.

## Required wiring outside P4 ownership

1. `mobile/src/services/index.ts` still sets `realServices` to `undefined`. P6 should wire the exported core service instances into the real bundle after the remaining API/offline services are ready.
2. After a successful `GET /v1/config`, call `cacheServerConfig(config)`. The helper validates and stores `serverTime` and limits. Until there is a valid server clock baseline, offline spending is blocked. A device reboot also requires a fresh config sync because Expo uptime resets.
3. Use `getSecurityStatus()` to feed the Security screen, including `debug`, `clockSuspicious`, score, key state, ledger status, and authentication enrollment. The current shared `IntegrityReport` and `mobile/src/services/types.ts` only type `rooted` and `isDevice`; P4 exposes the extended `CoreIntegrityReport` locally and did not edit those P0-owned interface files.
4. For ledger witnessing, send `ledgerService.head()` to the server. If `verifyChain()` reports only an anchor mismatch, `head()` returns the recomputed local chain head for online witnessing while spending remains blocked. Call `ledgerService.reconcileAfterServerWitness(head)` only after the server accepts that exact head without flagging it. Corrupt rows do not produce a head and require an explicit recovery policy.

Debuggable builds, rooted devices, and emulators are blocked by default. `setDevelopmentIntegrityOverride(true)` can bypass those integrity checks only when `__DEV__` is true; it never bypasses clock, ledger, or credential checks.

## P7 usage notes

- Call `selectForAmount` before constructing a payment, catch `ExactChangeError` to show its available denominations, and catch `OfflineSpendLimitError` for configured caps.
- Call `markSpent` before returning proof/QR data. The selected vouchers are moved to `spent_vouchers` before the call resolves, even if later signing fails.
- Use `conservativeNowSeconds()` for voucher-expiry and payment-deadline checks. `selectForAmount` and `signPayments` already apply this clock internally.
- Use `seenVoucher` before accepting a proof and `addVerified` only after P7 verification succeeds.

## Physical-device limitation

Clock checks compare the wall clock with Expo's device uptime. Expo documents Android uptime as excluding deep sleep, so a long sleep can be treated as suspicious and require an online config refresh. The phone test should confirm this behavior is acceptable for the intended offline interval. No claim is made that this is a secure hardware clock.
