# P4 manual steps

1. On the Android phone, enroll a fingerprint and a screen lock/PIN in **Settings > Security** (the exact label varies by Android version). Offline key setup refuses to proceed without a biometric or device credential.
2. After P6 wires the real services and server config cache, build/install the Android development build from PowerShell:

   ```powershell
   cd C:\5thsem\Projects\offline_upi\mobile
   npx expo run:android
   ```

   SQLCipher requires the configured custom native build; Expo Go cannot verify this storage path. Debuggable builds block offline spending unless P6 explicitly enables the dev-only integrity override.
3. Sync `/v1/config`, then test a multi-payment signing batch on the real phone. Confirm one system authentication prompt covers the batch, and that canceling the prompt returns no signatures.
4. Change or remove enrolled biometrics after key setup. The next key access should report `KEY_INVALIDATED`; confirm the app does not silently create a replacement identity.
5. Test a clock rollback and a rooted/emulator block. Restore the correct time and sync config before expecting offline mode to become available again.

These device-only checks cannot be completed from the laptop. The Jest mocks verify service behavior but do not exercise Android Keystore, device authentication, root detection, device uptime, or the compiled SQLCipher driver.
